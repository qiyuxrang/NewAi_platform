# 部门填报字段设计（SDD）

状态：2026-10-14 已确认并实现三类填报字段与流程；经后续整体上线要求及实际账号授权确认，财务前置包和最小迁移已在本机实际环境部署，售前、工程、财务账号已接通并通过只读验收。真实台账保存/发布仍按禁止写入约束仅在隔离环境验证。最新交付与证据见 [实施交付报告](general-manager-workspace-implementation-report.md) 第 9 节。

## 1. 设计取舍

- 三个入口仍叫 **售前填报、工程填报、财务填报**。产品/工程采用“列表 → 新增/编辑 → 保存草稿 → 授权提交 → 授权发布”；财务采用“本人记录 → 保存草稿 → 本人确认精确版本发布”，没有部门提交步骤。
- 售前主区 6 项、工程 5 项、财务 7 项；其他已有字段放在展开区。**主区表示优先填写，不代表全部新增为后端必填项。**
- 新记录的项目编号由界面生成并遵守现有唯一性校验；已有编号保持不变。来源、版本、操作人等由导入或系统维护，不让员工重复填写。
- 空白表示未知，0 表示已确认的零；不默认补零，不按描述猜阶段或进度。不自动合并不同表中的同名项目。
- 本期复用已有字段和校验，仅调整显示、录入与分组；不新增字段、状态或统计算法。

## 2. 售前填报：关注项目与跟进

依据产品工作簿的“商机”“温小朋-售前支撑”“Sheet5”“Sheet7”等结构，归并相近填写内容；原始记录和来源仍保留。

| 主区字段 | 填写方式 | 填写规则 |
| --- | --- | --- |
| 项目名称 | 单行文本 | 必填；使用能识别具体项目的名称 |
| 跟进人员 | 文本 | 建议填写实际负责人；不把填报人自动认定为负责人 |
| 项目阶段 | 下拉选择 | 标准新建必填；源表未标注阶段可保持空白 |
| 跟进日期 | 日期 | 可空；填写实际跟进日，不自动使用当天日期 |
| 项目进展 | 多行文本 | 建议写“目前情况、下一步安排”；不拆成新的字段 |
| 预计金额 | 标准模式为预计金额（元）；源表模式为折算金额（元） | 标准新建必填；源表未知金额保留空白，原始额度及单位在展开区保留 |

阶段沿用：线索、需求沟通、方案编制、报价、商务谈判、已赢单、已丢单。“成熟度”“预计签约时间”和自由文本不自动转换为阶段。

**展开区：**通用部分为项目概况、甲方对接人、项目定型、成熟度；源表模式再展示预计签约时间、推进计划、备注及已有跟进记录，不向标准记录写入来源专用字段以触发模式切换。预计签约时间保留原有文本精度，不强制把“某月”编成具体某日；推进计划沿用文本，不新建十二个月的任务系统。

**金额处理：**保留原始额度及原表单位。只有明确单位才沿用既有换算；“Sheet7”的预算标明万元，售前支撑表的“项目额度”不能自行认定为万元。已导入的原始额度与标准预计金额分别保留，不因简化表单而覆盖。

**列表建议列：**项目名称、跟进人员、项目阶段、跟进日期、项目进展、预计金额、操作。长文本单行摘要，完整内容在编辑页展开。

**本期舍弃：**手填序号、重复填写项目概况、KPI/绩效打分、费用汇总、七月与八月汇总表的重复录入。不删除原始资料，不把历史汇总重复计入当前项目。

## 3. 工程填报：关注实施状态

所提供文件夹没有工程模板，本节依据项目现有工程台账设计。

| 主区字段 | 填写方式 | 填写规则 |
| --- | --- | --- |
| 项目名称 | 单行文本 | 必填 |
| 项目负责人 | 文本 | 建议填写；沿用现有负责人字段，允许空值 |
| 实施状态 | 下拉选择 | 必填；使用现有状态 |
| 计划完成 | 日期 | 可空；不明日期保持空白 |
| 完成进度 | 百分比 | 必填，0—100，最多两位小数；由负责人确认 |

状态沿用：待开工、实施中、待验收、整改中、已验收、质保中、已结束。

**列表建议列：**项目名称、项目负责人、实施状态、计划完成、完成进度、操作。

**本期舍弃：**新增风险等级、现场日志、下一步任务、实际完工日、验收日期、工程合同金额。现有五项已能支撑实施看板；工程填报与产品报价仍是独立入口。

现有接口不允许空进度，因此未知进度暂不能保存为有效工程记录；不能用默认 0% 绕过校验。支持“进度待确认”需要另行修改业务规则，本期不纳入。

## 4. 财务填报：关注应收与回款

默认沿用所提供“应收总账”的源表口径。桌面文件“财务部.xls”与附件“应收账款盘点表2026（更新后）.xls”内容哈希一致，按同一份资料使用。

| 主区字段 | 填写方式 | 填写规则 |
| --- | --- | --- |
| 项目名称 | 单行文本 | 必填 |
| 业主单位 | 文本 | 建议填写，便于识别付款方 |
| 合同金额 | 金额 | 必填，沿用现有校验；未知不得填 0 冒充 |
| 年初应收 | 金额 | 对应原表“年初应收总额”；可空 |
| 应收结余 | 金额 | 对应原表“实际应收结余”；可空，直接维护已核对值 |
| 回款负责人 | 文本 | 建议填写实际负责催收的人 |
| 目前状态 | 多行文本 | 可空；保留真实回款情况，不新增固定状态枚举 |

**展开区一：主体信息。**类型、挂靠单位、挂账主体，保留原表含义。

**单位规则：**标准财务台账沿用系统的元口径。本次财务源表表头没有标明金额单位，源表编辑保留原始数值并提示“原表单位未标注”；正式接入时须核实单位，不直接缩放或把显示单位当成原表已核实信息。

**展开区二：月度回款。**用一张紧凑金额表分为“1—7月实际回款”和“8—12月计划回款”，每月可空；保留原有固定月份字段。原表标题为2026年，页面需明确提示此来源年度，不自动把这组数据变成下一年度。

**列表建议列：**项目名称、业主单位、合同金额、年初应收、应收结余、回款负责人、目前状态、操作。月度金额在编辑页展开。

**本期舍弃：**发票明细、银行流水、付款申请、成本利润、账龄分档，以及全年实际回款/滚动回款计划的新模型。

**必须保持的口径：**

- 合同金额、年初应收、应收结余分别维护；不以相减结果自动推定累计回款或本年回款。1—7月回款合计不能改称全部累计回款。
- 此源表没有应收日期，不补造到期日、逾期天数或账龄。
- 现有另一种“标准财务台账”使用项目名称、合同金额、已收金额、应收日期：已收金额必填，日期可空。财务主区 7 项适用于本次源表，不适用于标准台账；标准台账按其实际字段显示，不隐藏必填的已收金额。
- 统计模式由整本记录判定，新增/编辑接口却按单条记录校验：财务记录只有真实的年初应收、应收结余或来源工作表之一非空时才识别为源表。三者皆空的新记录须满足标准字段；已收未知时不可保存，不能补 0 或假来源绕过。前端说明原因，不承诺任意空值组合可存。
- 不提供台账模式切换按钮，不在同一本台账主动混入两种口径；已有空值、来源或混合数据保持原值与后端统计口径，不能为了表单简化自动转换。售前新增/编辑也按记录自身识别模式，不能仅因台账里其他记录有来源便省略标准必填。
- 台账截止日期沿用现有台账级信息；不另增每个项目的“数据日期”，也不把截止日期当作月份所属年度。

## 5. 共用规则与验收

- 编辑页使用蓝白风格、两列表单；金额统一标明单位，长文本跨两列。必填标记随实际台账模式显示，不以折叠隐藏必填项。
- 已有记录编辑时以完整原记录为基础合并本次改动，保留全部已支持字段；折叠、摘要或不展示不等于删除数据。导入来源信息只读，手工新增不伪造来源工作表或来源行。优先调用单记录新增/编辑接口，避免整本覆盖他人记录。
- 每次写操作携带当前 `expected_revision`；409 后保留未保存内容、重新读取版本并由用户核对，不自动重试覆盖。按钮依据接口 `permissions` 和台账状态启用，提交不等于已发布，不能默认填报人拥有发布权。
- 财务按 `record_meta` 的核实作者识别本人记录；他人记录及归属未知记录只读。发布本人选定记录时沿用 `expected_revision`、`expected_published_revision` 及每条 `record_id/source_revision/source_checksum`，由后台校验作者、最后修改者与精确草稿版本。财务无“部门提交/退回”按钮，不把通用 `can_publish` 当作其发布条件。
- 不建立新的客户、联系人或项目主数据系统；跨部门同名项目本期不自动关联。各部门维护其授权台账，总经理读取既有授权范围内的已发布结果。
- 标准售前新建缺少阶段/金额、工程缺少进度、财务缺少合同金额时，明确提示现有约束；不承诺草稿可以绕过这些校验。源表中已有可空字段维持可空。
- 验收须覆盖：三类新增与编辑、单记录模式识别、合法空值与真实零值区分、金额单位、阶段枚举、已有字段保存不丢失、源表/标准两种财务口径、本人/他人/未知归属记录、并发冲突、权限及发布后看板更新。源表年度只对可核实的原始来源标注，不从截止日期或已变为“手工录入”的来源名称猜测。

字段取舍与布局已按确认方案实施。未导入真实工作簿或修改实际台账；金额单位、来源年度只有可核实信息才标注，真实上线状态单独报告。
