## 手动测试准备

1. 使用本工作区的新前端构建和业务后端。此次未重启现有业务服务、未变更现有业务数据库；旧服务不一定已加载本轮改动。
2. 使用已有授权的测试账号，至少覆盖产品、人事、工程，以及一个没有业务权限的平台管理员。不要通过给管理员全部业务权限代替隔离验证。
3. 准备允许测试的设备清单、背景材料、JD、有效简历和 1–2 份 XLSX 工程清单。建议保留一份缺信息的样本。
4. 先用正常网络完成一条路径，再用浏览器开发者工具模拟失败。写请求断网后先查看后台结果，避免重复创建。

## 按顺序执行

| 编号 | 操作 | 应看到的结果 |
| --- | --- | --- |
| P0-01 | 产品上传清单及背景，生成蓝图，核对后继续生成三件套 | 每一步显示真实状态、需要人工确认的问题；缺失事实不应变成已确认事实 |
| P0-02 | 在产品生成中观察轮询，再刷新或按同一链接返回 | 任务可找回，同版本成果和历史不闪失；无虚构进度 |
| P0-03 | 产品补充附件时模拟回包丢失，恢复网络后刷新 | 只有匹配新来源及文件证据才移除待传文件；未核实前禁止再次发送；核对完成后不重复添加附件 |
| P0-04 | 查看产品成果版本、来源、审核问题，下载 Word/PPT | 文件可打开，内容完整；旧版本和待确认事项明确。下载成功不代表内容质量通过 |
| P0-05 | 人事输入招聘说明生成 JD，再确认 | URL 带 `task`；保存定位后生成过程不中断，未知薪资福利仍待补充 |
| P0-06 | 上传正式 JD 和多份简历，创建筛选批次 | URL 带 `batch`；创建后继续完成上传与启动，不丢待传文件，不多建批次 |
| P0-07 | 筛选中离开再返回，刷新；模拟进度接口断网后恢复 | 保留最后快照并标记未核实；恢复读取后显示真实数量；失败项单独计数 |
| P0-08 | 查看筛选证据和失败项，再按提示重试 | 结论能对应原文及位置；缺证据为 UNKNOWN；重试不改写已完成结果，尝试上限由后台控制 |
| P0-09 | JD 创建时模拟失联，点击“查看招聘历史” | 生成暂停，允许到历史核对；未提交说明离开后不自动保存；核对前不盲目重新生成 |
| P0-10 | 工程上传 1–2 份 XLSX，查看创建、执行、结果并刷新返回 | URL 带 `engineering_job`；创建成功不被后续读取失败误报；状态、次数和重试时间来自后台 |
| P0-11 | 下载工程草稿，核对校验摘要、取价来源、零价项和文件 SHA-256 | 下载经鉴权代理；缺校验摘要标待复核；计算与来源仍需逐项人工核对 |
| P1-01 | 业务后台进入“运行情况与资料权限核对”，选账号和部门 | 查看、AI 使用、下载分别给出实际文档标识；只读核对，不读取正文 |
| P1-02 | 停用授权、设置过期、移除角色/项目成员，再次核对并访问资料 | 对应权限被撤销；刷新后的业务访问被拒绝。其他仍有效授权可能继续授予同一文档 |
| P1-03 | 使用普通账号、无业务权限管理员、另一部门账号访问业务及管理地址 | 普通账号不能进入管理核对；管理员不会自动获得资料正文；跨部门资料不可访问 |
| P1-04 | 查看后台任务与模型调用统计，对照真实任务和调用日志 | 不把过期租约当作 worker 离线结论；不把配置限额当作剩余额度；未结束调用不算失败 |

## 发布前保留的验证

真实模型、RAGFlow、成本引擎的业务质量，权限隔离与撤权的实际环境演练，worker 重启恢复、备份恢复、反向代理超时及容量验证仍需完成。不要将本轮构建和模拟浏览器通过等同于生产部署通过。

JD 同步生成接口目前没有服务端幂等生成保证，网络失联时使用人工核对边界；HR 重试接口按失败项批量处理，不能逐条选择。未确认上传依赖安全上下文中的 Web Crypto 核对；无法取得哈希时保持未核实，不猜测成功。
