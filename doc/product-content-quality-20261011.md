# 产品正文质量修复与验收

日期：2026-10-11。适用技术方案、可研和由两份报告派生的演示文稿。本轮优先后端，沿用已人工确认的蓝图，RAGFlow 暂缓。

## 问题及处理

| 已发现问题 | 永久处理 | 不通过时的行为 |
| --- | --- | --- |
| 未提供的现有系统状况写成既定事实 | 区分项目事实、公开参考、设计建议和待核实事项；检查高信号现状和能力断言 | 拒绝保存该响应，返回具体段落及修正要求 |
| 跨部门、跨对象或否定证据被误当作肯定依据 | 拆分独立断言、核对同一对象与用途、排除否定证据；现状证据不能仅凭相同缺陷词匹配 | “不采用”不能支持“采用”，其他部门现状不能用于当前部门 |
| 自行添加备份周期、保留时长、性能等固定参数 | 同时检查中文和阿拉伯数值，按同一对象与用途核对；资料中的相同数字不能证明其他用途 | 无依据固定参数必须明确为待确认或有条件候选；仍不合格则停止 |
| 将公开技术资料当作本项目已实现能力、选型或合规证据 | 公共来源只支持明确归属的通用参考；不进入既有项目事实白名单 | 程序检查与全文模型复核共同拦截 |
| 续写复制原文，仅换编号或少量字凑篇幅 | 保存前跨已存章节检查全段近重复和实质长片段复制；常规章节的续写上下文保留完整已存正文，超长正文显式标记有界截断 | 沿用一次纠正预算，不合格响应不保存 |
| 相同数值被用于无依据的其他参数或部门周期 | 移除裸数字全局白名单；无单位参数也核对参数名称，所有角色匹配先核对明确对象及范围，部门事实不能升格全公司事实 | 已有两台服务器不能授权并发连接数为二；财务系统备份周期不能授权人事系统周期 |
| 项目总量被扩展成每个系统各有同量，或前句待确认掩盖后句固定小时周期 | 区分集合总量与逐对象分配；同一对象的通用别称精确归一，具名对象保留；并列断言的频率单位与支持的周期语法对齐 | 总服务器数量不能证明每套系统各配置同量；每个小时的独立固定运行周期也需自身依据 |
| 协议名称、指标名称、禁止承诺和认识边界被误当作固定参数或能力结论 | OAuth2/OAuth2.0 与 P99 仅在词汇标识局部识别；禁止承诺按局部范围处理；无法量化、无法评估不等于无法实现能力 | P99 的具体毫秒阈值仍须有依据；无法实现高可用及其后续独立保障断言仍检查 |
| 抽样片段误判整篇字数不足或把引用元数据当正文 | 提供全部正文的程序权威计数、真实截断边界；长文按连续片段覆盖全部正文 | 实质内容问题仍阻断；边界说明不替代内容检查 |
| RTO/RPO 混称，以及变更集、对象命名、哈希和恢复计时概念混淆 | RTO/RPO 明确混称进入程序检查；全部相关概念与保障边界进入生成和全文复核规则 | 错误术语或实质实现问题须纠正后复核 |
| 低基数与小分区因果倒置、PostgreSQL 只读表空间、Kafka 框架能力否定及 Alertmanager 抑制与聚合混淆 | 明确错写进入局部概念检查，正确否定、其他数据库归属及通知边界保留；分区性能和上线前验证顺序进入生成与全文复核规则 | 当前正文通过正常版本 API 修正，后续同类明确错写被拦截；程序规则范围之外仍需实际模型和人工复核 |
| 复核 JSON 能解析但字段类型错误，直接中断且不纠正 | 独立复核语义检查进入原有一次纠正路径，严格保留布尔值、字符串数组及长度边界 | 纠正后仍不合规则停止，不强制转换类型或清空实际问题 |
| 审查返回“不存在问题、符合要求”等无缺陷观察却判定失败 | 检查审查结论和问题列表的一致性，无缺陷观察进入原有一次纠正路径 | 实际缺陷原样保留；即便 `passed=true` 仍有实际问题，也不能通过 |
| 正常标准编号和软件版本被当作项目参数误拒 | 仅对当前公开来源确实出现的标准、版本标识局部放行；不把其中数字加入项目参数白名单 | 未引用的版本、借用编号数字形成的周期或端口仍被拦截 |
| 复核中断后丢失前面批次发现的问题，或者重复支付有效复核调用 | 每批持久保存严格响应、覆盖片段和实际成功调用证据；绑定输入、蓝图、正文、规则与路由 | 仅完整匹配的批次可恢复；原问题保留，不完整审核不能生成文件 |
| 历史 Word/PPT 或其他生成入口跳过新校验 | 全部生成入口统一当前质量检查和真实全文复核；绑定正文、输入、蓝图、规则与实际调用证据 | 过期审核和旧文件不能绕过新门禁 |
| 正文审核有效但报告载荷或图形文件已改变，仍复用历史 PPT | 重算报告载荷摘要，逐图核对实际安全路径、图形文件摘要与图表生成证据 | 更改报告或图形后不能复用旧 PPT；正文和图形必须共同匹配 |
| 图表锚点真实，但标题、说明、节点或连线额外编造数字、现状和能力 | 每张图只用自身 `evidence_block_ids` 指向的正文事实核对全部可见文字；节点、连线、分组及序列图消息与循环标题逐项检查 | 未引用正文、其他图的证据、待确认或条件性证据均不能支撑新增既定事实；错误图表不保存 |
| 图表把候选组件升级为已部署、已选型或已实现 | 除实体锚点外，还核对图中完整既有状态断言的已确认正文依据；限定语按局部断言处理，包括但、而、同时连接的后续状态 | 返回 `unsupported_diagram_state` 和可见字段位置；设计步骤、正确待确认表述和已确认事实保留 |
| 图表把内部来源标识显示给读者，或旧图表缓存绕过新规则 | 可见文字检查内部标识泄漏；图表缓存契约绑定正文质量规则摘要 | 内部结构 ID 不当作数量，可见标识和过期图表不能复用 |

## 生成与发布

长任务在模型派发前按当前用户和路由的滚动分钟记录等待调用额度，单次最多等待 120 秒；每秒重查权限、取消、租约、规则和总模型调用预算，事务外等待。等待不消耗调用次数，实际派发仍计数；并发抢占造成的真实拒绝会保留失败证据，不通过无限重试绕开限流。专项 `pacing-worker-targeted-r2-result.json` 为 82 项、主代理独立限流与审查恢复集成 `permanent-pacing-integration-result.json` 为 50 项，均无外部模型调用且运行源码未改变。

一次模型请求的 JSON 和语义纠正共用最多一次重试，并受原有权限、租约、总调用量和尝试次数约束。不得以宽松解析、类型强制转换或忽略实际问题得到“通过”。失败诊断保留具体问题、章节和段落位置，原始章节修订历史继续保留。

第四周期的真实纠正再次引入无据现状，后端因此补充局部候选纠错：仅章节完整四字段结构、原标题与章节标识、非空批准来源全部有效且存在质量问题时，单次纠正临时附带上一批完整候选，要求针对问题修复并保留其余有效分析。候选不是事实或批准依据，第二轮仍完整检查，不能直接保存第一轮内容。候选 JSON 最多 12000 字符，两条用户消息内容合计最多 14500 字符（不含系统消息）；超界回退原整批重生，不截断。候选仅在内存中的模型消息使用，数据库及诊断只留固定标志、摘要和长度；实际调用摘要同时绑定候选，章节 gateway/parser 调用关闭局部 LangSmith 跟踪，避免完整拒稿落入该跟踪。解析、结构或来源失败不附带候选，图表、蓝图及审核路径保持原合同。子代理隔离 Worker 78 项检查通过，真实模型效果和当前文件验收仍须独立证明。

生成纠正提示要求只返回目标根字段，不回显输入元信息或校验说明。JSON 可解析但字段集合不匹配时，诊断保留缺失与多余字段的数量；章节响应还可列出缺失的服务器预定义必需字段，范围仅限 chapter_id、title、paragraphs、source_ids，不保存模型多余字段的名称或值。纠正提示明确新增正文只指 paragraphs，其他必需字段仍须完整返回；严格结构合同和一次纠正上限保留。低基数与小文件的错误因果不能用尾随的“并非绝对规律”“需验证”免责，仍需改正论述本身。

正文请求同时把服务器端生成的质量规则放入系统指令，不能用资料或请求里的同名文本替换。未知运行数值默认说明确认方法与所需字段；已有设备总量不能直接推定各台的冷热、主备职责。实质错误仍由保存前门禁和全文复核阻断，提升指令优先级不替代校验。

续测补充了中文数量和命题范围：数量绑定到计量名词，不把“向系统集成商索取”的接收方当作系统名称；“业务系统数量为三套”保留数量名词的实际对象。具名财务、人事及源系统不能借用项目总量，“每套”“每一套”的逐对象配置也不能由总量反向授权。每一条核查结论是逐项枚举，“这一人工确认”不是一名人员；“唯一人员标识”“任一人员”“唯一台账”的连续词内片段也不能当作一人或一台的数量依据。该边界在正文与来源提取中共用，不能借这些词反向授权真实人数和设备数量。独立的8GB、90天、人数及配置数量仍检查。每日增量大小或增量数据速率可以是调查字段，其统计维度不能授权每日备份、每小时同步或未提供的数据量。

第七次真实生成进一步暴露了“项目拟整合的业务系统数量”和引号服务器“总数”的计数关系误判，以及“现有系统缺乏统一标准”的现状漏检；对应修复仍需保留具名系统、设备角色、现有与新增用途的区别。主代理独立补充探针另发现“不得新增”的负向来源反授权及必要性句式下相同状态命题的匹配问题，初次失败证据保留在 `final-readonly-review/parent-v39-observed-claims.json`。后一项正向事实对照已明确限定相同对象、数量和全部业务环节；笼统缺失描述不能支持更具体的现状。探针结果不等于整份模型响应、文件或当前任务已经验收。

第八次初始响应的诊断及独立正序对照暴露“服务器对象数量”的计数关系漏识。修复共用有限计数谓词和成对引号量值后的明确对象谓词，不使用附近出现服务器就整句放行的方式；具名类型、用途、采购新增、逐对象配置、否定或待确认资料、后续独立数值继续检查。原 97 个对照结果不变，42 个新对照及 132 项质量模块检查通过；主代理独立的 9 项对象关系、14 项前轮边界、201 项事实边界、20 项局部范围和审查缓存检查通过。实际响应未保存“上述”的前置句，不能据此补造指代或宣布整个响应通过。没有修改提示规则、项目事实、正文下限、尝试次数和模型预算；冷热职责的实际分配仍需全文复核独立审查。

第四周期首轮继续发现完整泛称“特定业务系统”的身份误判，现只把该完整泛称加入共用对象归一，保留财务、人事和带编号对象的区别。对于紧邻的一套业务系统停机条件及其余系统数据流隔离后果，只校验局部剩余计数，要求同一已确认业务系统总数减去明确的一套，不把整句当作免检内容；错误剩余数、具名子组、后续独立参数仍检查。来源中的该条件后果不能成为既定接入或分期配额依据；第某阶段或期的明确接入、扩展数量仅接受同阶段正向依据，不把库存总数自动当作阶段批准。修复经子代理 137 项质量检查、139 项原对照及 29 项实际/反向对照验证，主代理独立 10 项关系对照（含总数改为四套的控制）通过。此处是有限关系检查，不能代表任意复杂分期、数学场景或整份模型响应已验收。

第四周期续写还暴露“每日增量行数”字段及术语定义的范围问题。频率提取共用该统计字段边界，不能让字段名称反授权每日备份；实际行数仍另行检查。明确“统一/定义……概念/术语/表述……指代/定义/含义”的成对引用只限定引用中的术语，来源也移除同一局部定义片段，不能据此证明实际问题存在；任意引号、独立后续状态和数值仍检查。质量模块 141 项及 191 项原/本轮对照通过，主代理 225 项隔离集成及局部事实、审核缓存复核通过。主代理初次字段对照为 10/11，独立机器库存的正向样本仍含未解析的“这”指代；原结果保留，明确相同“现有两台机器”的正文与事实后 11/11 通过，未据此修改机器对象门禁或项目事实。真实的“这两台机器”诊断仍不能确认先行句；纠正提示要求已知数量沿用资料原对象称谓，不能借能力否定豁免数量。

阶段完整回归曾通过634项（632通过、2跳过），全部门1530项（1506通过、24跳过），但独立逐段阅读实际保存文章仍发现九类实质问题。这说明测试通过不能代替正文质量验收。已通过正常版本API修正固定资源阈值、增量路径唯一性、Schema注册中心与恰好一次的依赖混用、普通哈希保障过度、OAuth认证授权、RTO/RPO业务输入、存储分层因果、I/O控制和质量维度，并删除无依据要求至少十个实际冲突案例的数量。十二处修改、原文与修订均保留，修正后两章14383字符、34段已独立核验，输入事实和蓝图保持同摘要；完整三件套仍未验收。

模型还曾遗漏必需的source_ids。系统输出合同现明确示例空数组只表示字段类型，实际章节引用必须非空且来自批准来源，每次纠错后仍返回chapter_id、title、paragraphs、source_ids全部四个字段。严格解析不自动补齐缺字段或引用，不增加纠错次数；结构不合格继续停止。该澄清需要实际后续生成验证，不能承诺模型从此永不遗漏。

已把本轮高信号漏检加入有限检查：已设定判定/告警规则中的具体触发数值不因“当……时”自动变为假设；冲突案例配额作为独立参数用途检查。“不能断言”仅进入局部认知否定范围，来源中的该否定不能反授权可靠性或独立参数，不能豁免正文中的错误数量。恰好一次对模式注册的通用依赖、OAuth认证分类、哈希独自保障和无标记只能全量比对按明确关系校验；其他复杂因果加强写作与全文审核指令，不能宣称程序已穷尽语义真伪。

独立审查同时发现三处有限误拦，修复保留完整历史：OAuth枚举中的直接排除、同一次哈希核验已有隔离且受保护的可信基准，以及紧邻闭括号的明示纠正。限定只作用于对应关系，前句或无关动作中的基准、否定或拟议基准、仅凭普通哈希及后续独立错误仍阻断。最终质量模块152项、作者250项有限新旧对照通过；主代理独立当前源码152项模块、68项实际/修正正文对照及201项既有对照通过，审核缓存、批次全文重构、严格解析和图像绑定保持。235项集成是最后一次局部分类修正前的阶段记录，当前源码完整产品与全部门回归另行执行，不能把它标为当前最终全集通过。

否定推断、禁止设定和待确认限制只作用于局部命题。随后、然后或转折引出的肯定固定配置重新检查；“不会设置每日全量”不能作为“每日全量”的肯定项目依据。正文与来源采用相同范围规则，避免仅在正文端消除误报却让否定来源反向授权。生成政策只在系统消息中出现一次；纠正提示准确要求完整JSON，保留原字数目标及实质分析、步骤、输入输出和验证方法，不把内容失败一概称作JSON解析错误，也不增加纠正次数。

蓝图确认授权目录、分析范围和原条件，不自动证实范围中的现状或能力前提。写作、独立审核、图表和蓝图生成共用该边界；未知前提按原章节展开调查方法、判定条件和条件设计，审核也不能仅因正文未承认预设问题就判范围不符。原目录、来源和条件保留，具体分析和事实检查不能用空洞待确认清单替代。

实质片段复制检查有明确边界：连续精确片段至少 180 个非空白字符且占较短段落至少 35%；两段均不超过 2000 字时，也检查有序且互不重叠的精确片段，各段至少 50 字、合计至少 180 字且占至少 50%，并至少含一段 120 字片段。长段采用线性大小的后缀自动机，不对任意长文本运行平方复杂度差异比较。本轮定位并通过正常版本 API 清理了九处复制，保留较早原文及后段独有论述；清理后 57558 字、136 段技术正文的跨全篇检查未发现上述重复。
