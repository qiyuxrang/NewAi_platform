# 总经理工作台与部门填报入口优化方案（SDD）

状态：2026-10-14 已确认并实施。用户随后要求整体上线并逐项批准实际账号授权，现已完成本机实际库最小迁移、财务身份接入、构建产物部署及真实只读验收。以下保留设计与原冻结边界，最新交付、授权及未验证项见 [实施交付报告](general-manager-workspace-implementation-report.md) 第 9 节。

## 1. 目标与范围

为总经理提供统一的能力入口，为产品、工程、财务部门补齐台账填报入口。沿用参考截图的蓝白企业风格，保留现有企业 Logo，页面简约、清晰，各功能之间切换自然。入口名称统一优先使用四个字。

### 总经理侧栏

| 侧栏入口（按此顺序） | 复用现有能力 | 默认进入 |
| --- | --- | --- |
| 商机看板 | 产品事业部的项目机会页面 | 外部公告商机列表，保留筛选、详情、个人标记与刷新 |
| 文档生成 | 产品事业部的项目、资料、报告与成果页面 | 历史项目列表，可新建项目、进入详情和查看成果 |
| 产品报价 | 工程部的报价分析与任务页面 | 现有清单上传、成本测算及报价任务 |
| 知识检索 | 产品事业部的资料库与知识问答页面 | 现有知识库浏览、全文查阅及问答 |
| 财务看板 | 现有财务统计与已发布台账接口 | 只读查看合同、回款、应收等已有指标及项目明细 |

“产品报价”为总经理侧栏名称，内部仍保留现有成本草稿、待复核等真实业务提示，不改变报价性质。

### 部门填报入口

| 所属部门 | 新增入口 | 内容与现有流程 |
| --- | --- | --- |
| 产品事业部 | 售前填报 | 项目名称、负责人、阶段、跟进记录等现有售前台账字段；保留草稿、提交及授权发布流程 |
| 工程部 | 工程填报 | 项目负责人、实施状态、计划完成日期、实际进度等现有工程台账字段；保留草稿、提交及授权发布流程 |
| 财务部 | 财务填报 | 合同、应收、回款等现有财务台账字段；保留本人精确版本确认发布流程 |

工程填报与现有报价分析是独立入口；财务填报与总经理只读财务看板分开。部门台账看板只读取已发布数据；商机公告沿用采集与个人标记数据，不受台账发布流程控制。原有必填校验、数据来源和历史版本保留。

具体字段及取舍见 [部门填报字段设计](department-entry-fields-sdd.md)：售前主区 6 项、工程 5 项、财务 7 项，其余已有字段分组展开；不新增业务字段，不删除历史数据。

## 2. 页面与交互

- **左侧固定**：总经理显示原企业 Logo、五个功能入口、最近项目、账号与设置；部门员工在原有侧栏增加对应填报入口。当前功能以浅蓝底和蓝色文字突出。
- **右侧统一**：顶部路径与账号区保持一致，内容区使用统一的标题、留白、卡片、表格和按钮样式；仅右侧内容及必要的内部列表滚动。
- **文档内导航**：提供历史项目、新建项目、成果文件入口；项目详情继续使用原有资料、蓝图、报告和成果操作。
- **自然切换**：总经理五个页面共用同一外壳，Logo、侧栏宽度与顶部位置保持稳定；部门填报页延续同一蓝白风格。仅内容区轻量淡入，尊重系统减少动画设置。
- **桌面适配**：重点检查 1440×900 与 1920×1080，避免侧栏跳动、内容遮挡和整页横向溢出。

### 总经理只读看板：小而精的 BI 呈现

适用于总经理的商机、财务等只读看板：增加简洁指标图标与小型统计图表，复用既有数据与统计口径。

- **布局**：顶部 4—5 张紧凑指标卡，中间最多 2 张小图表，底部保留可筛选的项目明细。已有更多指标按实际需要换行，不强塞进一排；图表高度约 200—240px，让明细仍是主要内容。
- **图标**：指标卡使用 18—20px 统一线性图标，搭配浅色小底块；数字为主、图标为辅。侧栏五个入口沿用同一套图标，保留文字名称。复用现有图标和图表组件。
- **商机看板**：沿用公告接口的总数、今日新增、本轮新增、即将截止四项指标；有值时以小型独立条形图比较新增与截止数量，注明指标可能重叠，不画占比图。不把售前台账的七个阶段、跟进金额混入公告页面，也不以当前分页记录推算全量统计。售前台账与公告商机保持独立，本期不额外增加总经理侧栏入口。
- **财务看板**：标准台账展示合同、已收、待收、逾期待收四项指标，可用小环形图展示已收/待收构成，用条形图展示结清状态分布。源表台账按现有口径展示合同、年初应收、1—7月回款、应收结余、8—12月计划五项指标；图表选用年初应收与结余对比、现有主体/类型条目分布，不将不同金额叠加成合同构成。
- **风格**：白色卡片、浅灰分隔、蓝色主色；辅助色少量使用，无立体图、渐变背景或持续闪动。图例、单位和数值直接可读，鼠标悬停补充精确值；颜色同时配合文字表达状态。
- **真实数据**：卡片、图表、明细使用同一数据范围及筛选条件，台账显示来源和截止日期，公告显示既有更新时间。无数据或未知显示“—/暂无数据”，不补零、不画假趋势；原表金额单位尚未核实时明确提示并暂不绘制金额图，仅展示已核实的数量分布。后台返回“元”标签不等于源表单位已核实。
- **交互**：本期图表仅辅助阅读，不增加点击联动、钻取或新的统计维度；筛选、详情及页面切换沿用原流程。文档生成、产品报价、知识检索保留各自操作页布局。

## 3. 实现边界

- **文档生成与报价后端冻结（硬性约束）**：不修改两条链路的接口、请求/响应契约、权限校验、业务服务、任务队列、Worker、模型调用、提示词、生成/计算逻辑，以及成果存储和下载逻辑。两项能力仅调整前端入口、导航、布局和既有接口结果展示；发现后端问题单独记录，不在本次顺带修复，也不修改共用后端代码而间接影响这两条链路。
- 复用现有可维护页面组件、部门业务地址与接口；仅有旧构建产物的填报和看板页面补齐最小前端，不复制台账校验、统计及发布规则，不新增审批流程。
- 根据总经理已有授权展示入口；不扩大员工资料、项目、文件和知识库的访问权限。
- 保留现有上传、生成、计算、筛选、审批、下载及错误处理逻辑。
- 保留普通员工的部门页面和既有入口；仅增加产品、工程、财务的上述入口，不调整人事及其他业务功能。
- 财务员工身份接入仅按另获批准的最小前置包实施，实际库迁移另行确认；不通过更改所属部门、赋予产品/工程模块或借用总经理账号绕过。
- 前端包不修改数据库结构、业务算法、模型配置，不启动真实生成或报价任务；不导入用户工作簿或更改实际账号授权。后续正常填报使用现有接口写入数据，不意味着可改变数据库结构。
- 用户现有未提交改动予以保留。实施前按当前工作区记录受保护后端文件哈希，验收比较本任务前后差异；不能仅以 HEAD 为基准将用户已有改动归入本次。

## 4. 可执行拆分与技术前置

### 前端包：保持后端冻结

| 页面 | 路由与接口约定 |
| --- | --- |
| 商机看板 | 保留 `/departments/product/opportunities`；复用 `TenderOpportunities` 与 `product/opportunities/` 及现有配套接口 |
| 文档生成 | `/departments/product/documents?view=projects`；新建、详情继续使用原 `task` 等参数；成果子入口保留 `/departments/product/outputs` |
| 产品报价 | 保留 `/departments/engineering/estimate`，复用 `EngineeringWorkspace` |
| 知识检索 | 保留 `/departments/product/knowledge`，复用 `ProductKnowledge` |
| 财务看板 | 新增前端 `/departments/business/finance`，使用独立总经理路由守卫；调用现有 `/api/business/boards/finance/` 的 `metrics/distribution/records/source/scope` |
| 售前/工程填报 | 新增 `/departments/product/entry`、`/departments/engineering/entry`；先查询 `/api/business/ledgers/permissions/`，分别接入现有 `presales`、`engineering` 台账接口 |
| 财务填报 | 设计地址 `/departments/finance/entry`，完整财务员工接入以前置包获批并完成为条件；不能以不可访问菜单或静态表单宣称已完成 |

- 修改范围为 `frontend/src` 的导航、外壳、路由、台账展示与表单及必要定向检查；新增最小看板/台账组件，复用现有 `lucide-react` 和原生 SVG/CSS 绘图，不增加图表库。
- `frontend/src/business/api.ts` 仅增补 `/api/business/` 地址支持，既有产品/工程地址转换、认证头、上传、错误处理和下载行为保持不变。平台代理已经允许 `business` 根，无需修改代理范围。
- 保留产品、工程业务 URL，不另造总经理业务地址；总经理只保留一个固定侧栏和顶栏、每条业务路径仅一层 `BusinessSurface`。知识库内容分栏仍可调整，原员工页面保持原呈现。
- `DepartmentWorkspace` 需显式区分工程 `entry` 与报价功能，避免新增填报路由仍渲染报价页。先完成入口/外壳，再接入台账与 BI，最后验证页面流转。
- 前端按业务角色、部门、capability 和接口权限决定入口及操作；后端授权仍以原有台账 grant 为准，不将“不同部门”改成新的后端拒绝条件。总经理工作台只提供台账只读入口，不修改其历史 API 授权。
- 401 提示重新绑定/登录，403 显示真实无权限；包括同时具有管理员身份的总经理被现有看板拒绝的情形。无权限时不挂载业务内容、不改角色或安全规则强行接通。

### 财务员工身份前置包：已获准实施，实际库迁移待确认

设计时平台部门枚举、身份桥接仅支持产品、人事、工程，部门 CHECK 排除 `finance`。当前已实现财务增量分支和迁移；实际库只读核实仍为原三部门 CHECK，未迁移。`portal_profile` 在绑定、状态查询及每次代理请求中共用，财务接入包含已批准的最小后端前置包。

完整财务员工入口所需的具体前置包已获准：平台财务部门枚举、管理员分配选项、必要的部门 CHECK 增量迁移，以及共享 `platform/app/business_client.py` 中仅针对财务身份的增量识别。旧业务模型已支持财务，不需要更改文档或报价业务服务。

**该包会触及当前冻结的共享身份后端，未经明确确认不实施。**如获准，只允许上述身份分支和必要约束变更，原有三部门、总经理识别以及代理会话/CSRF/透传行为必须保持；整个 `services/business/backend/portal`、文档/报价业务接口、Worker、模型和任务系统继续冻结。实施前先用隔离数据库验证旧账号兼容、财务绑定及迁移/回退，不直接迁移实际库。

财务源表金额单位未核实，暂不自动导入两份原始工作簿或开放其金额图；这不阻止数量图、表单与空状态界面的开发。
