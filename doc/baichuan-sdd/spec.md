# 百川阁需求规格

版本 V1.4，2026-10-16。性质：本轮实施的可验收基线；真实本机权限与初始化已落实，资料真实性核实独立记录。

## 1. 目标与范围

用户按一个或多个企业资质及等级选择条件，获得同时符合这些条件的公司，查看公司详细资料、联系方式和有依据的团队能力，再进入公司官网首页。首批公司来自同事人工整理的 Excel；后续在网站维护。

一期包括双侧边栏入口、企业库、资质筛选、名称搜索、分页、详情、官网跳转、公司与人员资料新增编辑、一次性初始化。不含常驻 Excel 导入、自动官网抓取、全网企业采集、人才评分、企业排名、收藏对比、删除公司和独立统计大屏。

## 2. 使用者与数据边界

总经理与产品事业部用户通过现有账号、角色和模块授权访问百川阁。两个入口指向同一企业资源，而非复制两份资料。实际查询和写入权限由服务端决定，隐藏菜单不是授权措施。

FR-01：在总经理与产品事业部原有侧边栏各新增“百川阁”，保留原有功能、Logo和外壳；同一授权数据范围中的公司内容一致。

FR-02：列表、总数、详情、创建和编辑均执行相同的数据范围和权限约束。维护者范围按 D-02 落定；共享范围按 D-03 落定。不得把创建人当企业租户，也不得直接向全平台所有账号开放。

实施门禁：PORTAL_BAICHUAN_SCOPE_CONFIRMED默认False，READ_USER_IDS、WRITE_USER_IDS、READ_ROLE_CODES和WRITE_ROLE_CODES默认空。共享范围开启后仍须现有产品模块及总经理/产品身份；读取需匹配读取账号或明确读取角色，写入另需匹配维护账号或明确维护角色。仅配置读角色不能写，只有写角色却没有读取权限也不能写。角色配置仅接受general_manager/product。用户已确认两类工作台均可查看、新增和编辑，本机部署已显式配置对应读写角色；其他部署不得据此自动开放。

## 3. 七类资质字典

下列名称和等级来自用户提供的资质列表图片，仅作为本功能的录入与筛选字典，不表述法规或高低等级替代关系。

| 代码 | 显示名称 | 精确等级值 |
| --- | --- | --- |
| electronic | 电子与智能化工程专业承包 | 1=一级，2=二级 |
| labor | 施工劳务资质 | 不分等级，grade=null |
| cs | CS 信息系统建设和服务能力等级认证 | 1=一级，2=二级，3=三级，4=四级，5=五级 |
| cmmi | CMMI 软件能力成熟度模型 | 3=三级，4=四级，5=五级 |
| ccrc | CCRC 信息系统安全集成服务 | 1=一级，2=二级，3=三级 |
| itss | ITSS 信息技术运行维护服务符合性认证 | 1=一级，2=二级，3=三级，4=四级 |
| security | 安防工程企业设计施工维护能力 | 1=一级，2=二级，3=三级 |

FR-03：七类固定顺序如上，只接受该类别合法等级。grade 是字符串枚举，不进行数值高低比较。人员证书和其他类别的等级不能作为该类命中依据。

FR-04：默认精确匹配。只选电子与智能化二级，不因公司具有一级而命中；CMMI 五级不自动满足三级。

FR-05：同类多个具体等级取“或”。勾选 electronic=1、2，只要具有该类别任意一个所选等级即可。

FR-06：不同类别取“且”。每个已选类别均须找到该公司自己的一条匹配记录，记录的类别、具备状态和等级须同时满足该项条件。允许选1至7类；同公司同类多条记录仍只返回一家公司。

FR-07：未选类别不限制，额外资质不妨碍命中。每类支持“不限”和“具备即可”；“具备即可”与具体等级互斥；取消最后一个等级回到不限。施工劳务只有不限/具备，不显示等级多选。

FR-08：区分以下状态，不能把空白当作否定：

| 录入状态 | 数据含义 | 匹配具备即可 | 匹配具体等级 |
| --- | --- | --- | --- |
| UNKNOWN 或无记录 | 尚未提供或待核实 | 否 | 否 |
| ABSENT | 已明确不具备 | 否 | 否 |
| PRESENT，grade=null | 具备但等级待补充；劳务为正常不分级 | 是 | 否 |
| PRESENT，合法grade | 已录入具体等级 | 是 | 等级相等才命中 |

同公司同类别可有多条 PRESENT 记录；不能同时存储相互矛盾的 PRESENT 与 ABSENT/UNKNOWN 记录。出现矛盾输入，提示人工处理而非默认取正面值。

## 4. 查询与浏览

FR-09：公司名称搜索与资质条件共同生效。空名称搜索不限制；修改查询回第一页；清空恢复全部不限及空名称。服务端在全部授权公司中筛选后去重、计数和分页，不能仅筛选当前加载的一页。默认页长20，稳定按名称及内部ID排序；非法分页输入明确报错。

FR-10：列表包含公司名称/地区、资质及等级、联系方式、详情操作。名称和详情操作均可进入完整详情；详情展示该公司的全部已录入资质，并标出命中项。从详情或浏览器返回恢复筛选、名称、页码与浏览位置。

FR-11：详情提供官网首页的新标签入口；仅接受合法 HTTP(S) 地址，不接受脚本协议或带凭据地址。没有合法地址时隐藏官网入口，不制造地址或搜索链接。应用不自动访问、抓取或校验官网在线状态。

FR-12：公司基础资料包含名称、可选统一社会信用代码、地区、地址、简介、联系方式、来源和核实日期。数据层保留完整字段；2026-10-16用户追加要求后，详情只展示已填写的实用资料，信用代码、核实日期和系统修改时间不作为页面字段展示，空字段/空板块隐藏，不以假值补齐。来源及原始声明默认折叠，仍可完整展开追溯。证书编号/有效期有资料才展示；未知有效期不显示有效。不自动加入用户未选择的“证书有效性”筛选。

FR-13：核心人员选填，可记录姓名、岗位、部门、专业方向、职称认证、代表项目/成果、可选汇报关系、来源与核实日期。有明确组织关系时才能展示架构；不推导完整组织图，不自动评定优秀程度，个人证书不进入企业资质筛选。

## 5. 新增与编辑

FR-14：有维护权限者通过页面新增公司；公司名称必填，其他资料可补充。能否维护由服务端返回的权限决定，不默认所有查看者都可写。内部公司 ID 在改名时不变，资质与人员保持正确归属。

FR-15：编辑基本资料、资质和人员作为一份公司资料原子保存。需要预期版本号；版本已变时返回冲突，不覆盖他人更新。输入错误或保存失败保留用户输入。关闭未保存表单提示确认。已有非空信用代码重复时不能新增第二家公司；同名不同信用代码不能自动合并，缺少信用代码的重名应提示疑点并人工判断。

编辑可明确修正/清空子项，不能因为请求漏字段或校验失败丢失原资质和人员。本期不提供删除公司操作。若编辑成功使公司不再符合原筛选，刷新结果并说明原因，不伪装成保存失败。

## 6. 一次性初始化

FR-16：Excel 只用于首批资料初始化。目标企业资料主表一行一公司；七类资质各列填写等级；人员表一行一人并准确关联公司；填写说明解释缺失值和等级。现有收集表若一行一项资质，先核对主体再归并，保留所有原始等级和来源行，不直接按资质行创建多家公司。沿用已交付模板，不要求同事因列名差异直接重做现有收集成果。正式页面无 Excel 上传或批次导入入口。

FR-17：初始资料到位后先只读预检，记录文件指纹、来源行、字段映射、重复及冲突、人员归属疑点；预检零业务写入。处理并确认预检结果后再执行初始化。相同输入重复执行不新增重复公司/资质/人员，不静默覆盖后来页面维护的数据。失败回滚，不把部分成功写成全部完成。同类多等级在备注明确列明时逐项核对，不静默只保留一个等级。

初始化命令已实现，正式执行须提供经人工确认的清单及有维护权限的现有操作人。列名差异通过显式映射处理，人员必须唯一关联主表公司；同名不能自动合并。备注须保留原文并人工确认，多等级须归一为多条资质记录；整份资质替换映射必须覆盖原行所有非空类别，包含未知和不具备，不能用空数组或遗漏类别丢弃资料。数据库事务失败与提交后回执写入失败分别报告；回执缺失不能代表未导入，应凭原确认清单核对或重跑。
