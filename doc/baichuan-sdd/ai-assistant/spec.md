## 需求清单

### AI-FR01 浮动入口和单一对话

- 入口仅在有百川读取权限的相关工作台页面出现，默认收起；不替换既有侧边栏或增加独立大页面。
- 点击展开覆盖列表右侧的面板，桌面列表尺寸不变；面板之外仍可操作。窄屏可使用适配后的覆盖面板，不能溢出屏幕。
- 一个输入区同时支持文字、附件、发送、取消当前任务。用户不先选择“需求模式/文件模式”，也不填写多步骤向导。
- 收起面板保留对话与筛选；后台执行继续，完成后入口显示状态提示，不强制再次弹开。刷新后可恢复授权会话和执行状态。
- 角色高度初定约 110 CSS px。采用归档透明图、柔和阴影与轻微悬停反馈；不得声称是已生成的 3D 模型。支持键盘、清晰焦点、减少动画设置和实色背景降级。

### AI-FR02 白话需求与连续追问

识别资质类别、等级关系、地区、主体、时间、附加条件、输出字段和条数；将文字转换为受校验的条件树。追问继承上一轮条件并生成新版本，不悄悄覆盖另一轮正在执行的结果。条件摘要自然呈现在对话内，不要求每次批准。

### AI-FR03 文件自动拆解

- 首期交付可提取文字的 PDF、DOCX；扫描 PDF 必须有实际可用的 OCR 才能识别。OCR 未就绪、加密、损坏或超限时明确告知，不能声称全文已解析。
- 文字指令与文件共同解释；附件可只上传不附带文字，默认提取投标人资格和资质匹配条件。引用文件名、页码或段落/表格定位。
- 区分投标人、联合体成员、制造商、人员、产品等要求；区分必需项、评分/优先项、示例和一般说明；识别“且/或”“其中之一”和适用范围。
- 冲突或歧义在对话内说明，能独立执行的部分继续；未解决的关键条件使最终资格结论保持待核实。补充文字不能无提示地抹去文件硬性条款。
- 原始 DOC、压缩包及其他格式首期不承诺解析；显示支持格式。旧 Excel 资料核对属于维护流程，不因上传文件就覆盖数据库。

### AI-FR04 确定性匹配与等级规则

- 模型只输出合法结构化条件，不执行模型生成的 SQL、脚本或工具指令。
- 既有七类资质仍支持；精确等级沿用手工筛选语义。同类不同等级的“或”、跨类的“且”必须保留。
- AI-D23：只写明确等级（如“CCRC二级”）时默认精确等级；仅原文明确“及以上/不低于”等关系才可提取对应关系，不能自行扩大。表达不清时保留待澄清，不猜高低方向；此约束也适用于制造商、人员等主体。
- “二级及以上”等关系只能由带来源和版本的类别规则映射；不同认证的等级方向不能用字符串/数字大小统一判断。不支持的类别和规则标为未覆盖，不能自动当成满足或忽略。
- 按证书持有人及适用范围匹配，集团、子公司、制造商和人员的证书不能随意归给投标企业。人员资格没有结构化证据时不能据简介推定满足。

### AI-FR05 可解释结果与不确定性

- 返回“已确认匹配”“待核实候选”，并提供被排除原因的查看方式。每项硬条件输出满足/不满足/未知/冲突及证据。
- 已确认匹配须全部硬条件有有效且适用的证据；已知失败则不满足；无失败但有未知/冲突则待核实。优先项只排序，不能抵消硬条件失败。
- 有效性按招标要求的相关日期评估，缺日期显示默认以查询日核对；证书区间不完整、撤销状态未知或来源不足时不虚构有效结论。
- 零匹配说明本次范围、硬条件和资料缺口，不能断言市场上不存在企业；不能偷偷放宽条件。用户明确要求放宽才生成新的条件版本。
- 解释可追溯至记录、网页正文/证书及文件条款；搜索摘要本身不等于证书已核实。不生成无定义的“综合匹配率”。
