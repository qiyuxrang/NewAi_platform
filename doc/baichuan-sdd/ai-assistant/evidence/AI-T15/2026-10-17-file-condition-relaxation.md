## 最终行为

- 用户完整文字命令 `取消文件中的 ITSS 硬性要求`：精确识别已知类别，只删除已确认文件来源、位于安全 all 路径的对应谓词，保留其他文件要求和用户文字条件，生成新的条件/结果版本。此窄指令采用确定规则执行，不需要模型批准。
- `取消前轮文件全部硬性要求`：移除所有已确认文件来源的完整要求，包含完整 OR/NOT 逻辑组；不局部重写内部布尔分支。若还有用户文字条件则继续匹配；没有剩余可执行条件则明确等待输入，不隐式检索全库。
- 仅取消某类别而该类别位于 OR/NOT 组合时，保留原条件、进入 awaiting_input，释放租约。提示提供真实可执行的完整命令 `取消前轮文件全部硬性要求`；随后用该命令可整体移除已确认文件组，测试验证没有反复澄清循环。
- 逐谓词附件 source_refs 标记文件来源；最初纯文件输入可把其全部 must 作为文件要求。后续 checkpoint 固定 `file_requirements`，因此明确取消后不会在下一轮依据旧顶层文件引用复活已取消要求。历史混合输入不能分清来源时保守等待，不猜测用户条件归属。
- 否定、引用、说明文字不构成取消授权。附件中的取消指令与模型自行增加的取消字段均无权执行。取消命令同时带新附件时询问前轮/新文件范围，保持原条件。
- all 合并递归扁平化、同义谓词去重并合并引用；嵌套 OR 保持原逻辑。不会每轮重复把完整前 must 再包一层。原快照和已生成的导出未被写回。
- 取消审计记录当前消息 ID 与被移除谓词的稳定哈希；仍使用正常 owner/scope、预算、租约/fence 与不可变结果版本边界。
- 取消与新附件范围冲突后，下一轮明确回复会自动续接同 owner、同对话的待处理附件；附件 ID 在新任务初始入队时绑定并参加 payload 哈希，不修改已入队 payload。已有 completed 解析复用，不重复解析。模型失败保留待附件与前轮条件，后续输入或 retry 能恢复；仅在成功形成新条件版本后消费待附件标记，新文件硬性要求仍进入文件 guard。跨 owner/会话引用拒绝，已知文字条件不会误归类为文件要求。
- 导出失败回复对旧任务缺少 condition_revision 的情形从关联消息/固定快照取版本，失败能落为 failed 并释放租约；网关超时等错误使用现有固定白名单 message，不暴露上游正文，也不误报为路由未配置。
